# 基于 GPT-6 Astra、Codex 与 SolidWorks 的建模及装配能力验证汇报

日期：2026 年 9 月 14 日

项目：SolidWorks CAD Agent

阶段：实验验证与工程经验整理；尚非制造级通用产品

## 一、汇报结论

本项目已跑通“输入资料整理—原生零件建模—静态装配—独立几何/位姿验证—发现问题并修正”的链路。对于尺寸清晰的板类、支架类机械零件，已在指定案例上完成可编辑特征重建和原件布尔几何对比；对于完整机械手，重建了 8 种自制件，并与保留的采购件共同完成 26 个叶级零件实例的装配。

完整装配最终 43 条新建配合全部有效，保存重开后组件位姿与输入一致，未新增干涉。但首次装配虽然 43 次接口调用都成功，仍因方向转换错误产生了翻转解；修正后才通过。复杂扭转法兰只得到部分符合图纸的有效实体，体积仍与参考相差约 -7.92%，不能认定精确复现。

因此，当前成果证明的是 **在明确输入、可用 CAD API 与验证闭环支持下，模型能承担一部分工程建模和静态装配工作**，而不是“任意图纸全自动还原”或“无人工参与的工业设计”。

## 二、目标与本次整理范围

验证目标包括：自然语言驱动 SolidWorks、从图纸建立原生可编辑零件、多零件真实配合、发现失败原因并形成可复用流程。此次只整理代码和历史证据、撰写说明并更新仓库，不进行新的 CAD 建模或性能测试。

公开仓库保留核心执行算法、配置模板、策略和人工整理的经验；不上传执行产生的 CAD、PDF、录像、截图、日志、原始测量 JSON 或完整工业尺寸。相关实测数据仍在用户本地，汇报中的数值是对已有证据的摘要，不是本次重新测试所得。

## 三、能力来源：不是单一模型或单一 Skill 的能力

| 来源 | 实际贡献 | 需要避免的误解 |
|---|---|---|
| GPT-6 Astra | 理解图纸/文字、关联视图、选择建模特征、编写调用代码、解释测量差异并提出修正 | 不直接计算 CAD 实体内核，也不意味着每次读图都正确 |
| Codex | 提供 Agent 工作环境，调度文件/终端工具，观察输出，组织阶段与恢复、报告结果 | 不是另一套 CAD 软件；一次成功对话不等于已经产品化 |
| SolidWorks 官方 COM API | 允许程序创建草图、拉伸、切除、放样、螺纹和配合，读取模型和量测 | API 返回对象或无错误码不证明符合工程意图 |
| SolidWorks | 原生特征树、实体几何、布尔运算、配合求解、保存与重开 | 合法几何仍可能不是用户想要的形状或装配朝向 |
| 工程输入与用户澄清 | 清晰尺寸、装配关系、单位、采购件范围、局部放大图与歧义解释 | 不能忽略人工澄清和原模型派生信息，宣传为纯盲测 |
| 脚本与验证流程 | 固化单位、对象选择、日志、布尔差分、位姿/干涉检查及失败恢复 | 重复成功有一部分来自已有代码经验与缓存，不能全归因于模型从零思考 |

最初仓库选择了外部 SolidWorks MCP 作为封装入口，并完成过服务握手与工具发现等准备验证。后续本地单件和装配案例主要由 Windows PowerShell 5.1 加 C# interop 直接调用官方 COM 完成。**不能将这些 COM 成绩直接写成“指定 MCP 已全面验证”。**

当前工作中，经验通过提示词、代码、文档和检查规则保存；没有证据表明进行了模型权重训练或微调。Skill 可以把这些流程包装成 Agent 可发现的入口，但不能替代 SolidWorks 安装、合法许可证或执行器。

## 五、主要弯路与修正

### 1. “草图完全约束”仍可能把形状约束错

046 首次建模中，自动关系推断改变了钻尖轮廓，将预期 118° 钻尖变成 90°，并影响孔径和圆柱深度。通过图纸几何体积验算发现差异后，关闭创建过程中的自动推断，并将自动关系限制为必要的水平、垂直和重合；重建后再验证、冻结、与原件比较。

经验：不能把全约束当作几何正确的替代指标，必须同时核对尺寸和实体。

### 2. 放样接口成功但产生无效实体

扭转法兰首轮放样 API 返回成功、特征错误码为 0，但截面环绕方向或连接点对应不一致，产生了无效实体。修正连接对应后，改为逐段检查实体合法性，再检查最终两实体关系。

用户随后提供下端局部放大图，明确了部分间隙和隐藏轮廓解释。修订后体积误差反而增大，说明不能以“调到总体积更接近”为唯一目标。缺少曲面导向线、切向权重和完整连续性条件时，无法唯一恢复原曲面，也不能把差异唯一归因于曲率。

经验：端部尺寸、连接拓扑、合法实体、连续性和总体积应分别验证；图纸不完全定义时要保留假设，不虚构唯一答案。

### 3. 43 条配合都无错误，整体仍装反

完整机械手首轮装配把底层平面参数方向误当作实体面外法向，错误转换了 12 条平面配合的对齐方向。求解器仍找到数学上满足重合/同轴条件的另一种解，导致模块翻转，干涉对数由原模型 2 处变成 12 处。

诊断对比了源面和重建面的 `Face.Normal`、`Surface.PlaneParams`、`FaceInSurfaceSense()` 及组件变换，确认底层曲面方向变化而实体外法向保持不变。八种重建件已通过实体等价检查，因此只修正这类对应平面的方向转换，保留圆柱轴转换逻辑，重新建立配合。

第二轮 43/43 配合有效，全部组件位姿符合输入，无新增干涉；两处继承干涉的组件对与体积也与原模型一致。第一轮失败装配和录像均保留，没有用固定所有零件或删配合掩盖问题。

两轮均直接使用输入中的原始组件旋转矩阵作为初始朝向，只将非基准件的平移分散后求解。这个设置减少了朝向搜索难度，必须计入辅助信息；不能把这次结果描述成从任意随机姿态或仅凭 PDF 自动找到完整装配方向。

经验：必须至少分开报告“接口成功率”和“整体装配通过与否”。详细分析见 [装配复盘](assembly-postmortem.md)。

### 4. 录屏成功不等于展示内容完整

本轮录制了主屏，但主屏是最大化 SolidWorks，没有同时显示 Codex 对话。核心视频剪掉了准备、验证和失败排错阶段，只保留建模与修正后的装配。

经验：录制前先抽查实际画面，确认布局和可见内容；最终视频必须注明剪辑范围，不把视频时长当全任务耗时，不通过剪辑隐瞒首次失败。

## 六、局部模块整体移动的实际含义

用户观察到的过程确实存在，但需要区分两种情况。

第一种是保留的采购子装配：缓冲器、真空相关组件等原本就是 SLDASM，内部零件关系被保留，作为一个顶层组件整体插入。

第二种是总装内临时形成的配合连通组：先将 050 与 047 配合，再将 059 接到 050，随后把 047 接到固定的 046。此时已经相互连接的零件随求解器一起归位，视觉上像“先组模块，再整体安装”。这些自制件仍位于总装顶层，**没有新建它们对应的子装配文件**。

因此可以沉淀“按配合图逐模块组织执行”的经验，但当前不能声称已实现自动识别模块、自动生成子装配或优化装配工艺。按固定基准向外装配是后续可尝试的优化方向，不是本轮新增验证结论。

## 七、能力边界与风险

1. **输入完整性。** 三视图不一定定义所有曲面、内部结构或装配关系；尺寸、剖视、配合面和运动意图缺失时，需要用户澄清或允许假设。
2. **几何复杂度。** 本次通过的自制件主要是拉伸/切除、孔槽、倒角和钻尖。任意自由曲面、复杂放样、曲面修补、复杂薄壁结构尚无系统验证。
3. **参数化成熟度。** 原生特征可编辑不等于全约束；完整机械手的 54 个草图欠约束已明确披露，不能称为完整设计意图重建。
4. **装配语义。** 静态位姿正确不证明运动全行程不碰撞，也不证明受力、强度、公差、紧固件规格和工艺可行。
5. **材料与螺纹。** 名义几何、材料、质量、装饰螺纹和真实牙型必须分别检查。ModelMania 的材料缺项和插销未闭环说明不能合并宣传。
6. **执行环境。** 依赖 Windows、已授权 SolidWorks、本机模板与 interop；实测为 2026 SP0.0。模型数据的“SW18 可编辑”目录名不是已验证在 SolidWorks 2018 上运行的证据。
7. **状态与接口。** 共享会话、弹窗、文档切换、缓存拓扑索引和超时后部分完成，都可能导致误操作；一次只允许一个控制端。
8. **测评有效性。** 本地原件派生的图纸和朝向提示、用户补充解释、既有脚本都会影响成绩。没有跨模型对照、足够样本或隔离盲测，不能推出 Astra 的普遍成功率。
9. **迁移成熟度。** 参考装配器仍有案例命名与固定基准约定，本次去除了机器专属路径，但没有宣称完成跨案例通用化。

## 八、效率与可复用流程

完整机械手八种自制件的实际建模约 2 分 25 秒；首轮装配至最后配合约 3 分 05 秒；方向修正后的装配约 2 分 10 秒，含保存等画面的录屏约 2 分 14 秒。核心剪辑约 4 分 40 秒。

这些数字不包含资料提取、图纸整理、脚本准备、验证和排错。第二轮采购件已缓存，不能把时间减少全部归因于推理或算法优化。此前提出的“依据经验 versus 从零思考”对照测试并未正式执行，因此没有可靠的性能提升百分比。

可以复用的内容：统一单位和坐标、图纸/装配输入契约、正确面方向、单会话串行操作、孔槽操作模板、源模型隔离规则、阶段保存、合法实体和布尔对比、位姿/干涉基线、首次失败留痕、录屏前抽检。

不应固化的内容：某一模型的固定特征顺序、特定零件编号和尺寸、未经验证的“永不翻转”规则、某个模型的专用提示词。换模型后建模逻辑可能变化，但输入约定和验收条件应保持稳定。

## 九、项目发布建议

当前以 **代码仓库** 为主体：保留可审查的执行器、离线测试、配置模板与复盘文档；后续添加薄层 Skill 指导 Agent 正确调用同一套代码。面向更广安装分发时再考虑插件，而不是把所有底层逻辑塞进 Skill。

Skill 支持指令、可选脚本和参考文件，它与代码仓库可以共存；官方也提供面向分发的插件路径。[OpenAI：Build skills](https://learn.chatgpt.com/docs/build-skills)

当前不宜直接对外宣称通用自动 CAD Agent。建议标注“实验版，已验证指定单件及静态装配案例”。跨案例配置、输入校验、可恢复执行与兼容性应在后续获准测试后逐步补齐。仓库尚无 LICENSE，本次不替发布者选择开源许可证。

## 十、建议的汇报口径

> 我们验证了大模型通过 Codex 调用 SolidWorks 官方 API，完成清晰图纸辅助下的原生零件建模与多零件静态装配。完整机械手案例最终 43 个新配合有效，几何和装配位姿通过独立检查；首轮曾出现接口无报错但朝向错误的问题，已定位并修正。复杂曲面、完整参数化设计意图、运动与制造级验证仍存在明显边界。当前成果适合定位为可复用的实验工具集和人机协作流程，而非任意工程图的一键工业级重建系统。
