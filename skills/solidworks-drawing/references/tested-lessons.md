# Lessons from the first sample

Verified environment: SolidWorks 2026, official COM, Windows PowerShell 5.1. These are observed local issues, not universal SolidWorks limitations.

- Sandboxed GetActiveObject may return MK_E_UNAVAILABLE while SolidWorks is running. Run the scoped COM command with the environment's approved escalation mechanism; do not launch another SolidWorks instance or use UI clicking as a workaround.
- Script policy may block `-File`. Invoke the known script via `& ([scriptblock]::Create((Get-Content -Raw -Encoding UTF8 -LiteralPath '<run.ps1>'))) <arguments>`. Do not change the machine's execution policy.
- Standard orientation names are localized. Read GetModelViewNames instead of hardcoding English names.
- API lengths and angles use metres/radians. Plans use mm for sheet/model positions; conversion happens once in the executor. Native GetOutline includes a margin beyond the visible shape; it is useful for layout checks, not exact geometry size.
- Associated dimensions: use visible model vertices with SelectData.View, then compare the underlying IDimension.SystemValue against the expected measured value. Never override displayed dimension text to hide a wrong selection.
- Circular-edge label selection by XY and radius alone is ambiguous when multiple Z levels exist. Use persistent references and verify that the edge is visible in the selected drawing view. These labels are notes attached to geometry; they are not Hole Wizard callouts.
- Drawing-context edge proxies can return different persistent-reference bytes from their source-part edges. Resolve the source reference first, then find a unique visible circle with the same full XYZ center, radius and axis (axis sign may reverse). Reject zero/multiple matches. This preserves source identity without relying on screen location.
- A straight section line must be transformed from model coordinates to drawing coordinates, then into the parent view sketch before CreateSectionViewAt5. Do not render a fake section in a PDF.
- The initial sample contained native dimensions, notes and a table, but full annotated PDF export returned false/error 1 and omitted content. Changing fonts, hiding only the table, reopening and toggling PDF options did not fix it. Exporting with all annotations hidden succeeded for geometry only. The final supplemented PDF was a separate ReportLab overlay, not a fully native export. Do not repeat those diagnostics automatically.
- Later Windows Computer Use reproduced two consecutive native export dialogs: `Arial Unicode MS` was not correctly installed and text might be missing; then `PDF Export: Unhandled exception`. The warning names a fallback font, not necessarily the annotation's configured font. Official explanation: https://files.solidworks.com/Supportfiles/Release_Notes/2024/English/relnotes.htm#Technical_Alerts . Changing all document defaults, annotation formats and table cells to SimSun or STSong still returned false/error 1 on this machine; STSong was saved/reopened before export. Do not claim this issue is fixed by switching fonts. Proper availability of Arial Unicode MS remains to be resolved, and the exception may require further diagnosis after that.
- Font coverage must include engineering symbols: locally installed SimHei lacks literal U+00D8 `Ø`, while SimSun, STSong and Microsoft YaHei cover the sample's characters. Coverage alone did not prove PDF export compatibility. Font-family names are localized by process culture (e.g. SimHei versus 黑体); use the actual name returned in the COM execution environment. A missing font may invoke the unavailable Arial Unicode MS fallback.
- `IExportPdfData.SetSheets(1, null)` returned false locally; use specified-sheets mode (3) with actual sheet names and verify the return. This is separate from the font failure.
- The optional `FontPdf.cs` helper repairs fonts in a new drawing copy, including defaults and cell formats, then saves/reopens and attempts one native PDF export. Its font replacement and source-drawing preservation were tested; it has not fixed the missing Arial Unicode MS issue. See [font/PDF repair invocation](pdf-font-repair.md).
- ActiveSketch can remain non-null in a drawing even after EditSheet. That alone does not prove the user is editing a sketch.
- A verified delivery workaround combines native SaveAs geometry (annotations temporarily hidden) and native Microsoft Print to PDF annotations. Native printing alone retained Chinese text but lost model contours locally. `IPageSetup.Scale2` uses percent: 100 gives original sheet scale; 1 shrinks the page content to 1%. Matching A2 paper and composition alignment were verified. Use `export_pdf.ps1`, inspect the final render, and distinguish composed native output from the unresolved SaveAs font defect. No ReportLab-drawn annotations are involved in this route.
- No original source CAD was saved during the sample. Hash checks verified unchanged source files. Restore any temporarily changed configuration, and never save the source.

Keep private model paths, dimensions and case data in the user's run directory. The installed generic skill must not bundle the industrial sample. Actual validation results live in the run's report, not in unconditional skill claims.

## Batch lessons

- Native diameter dimensions use the selected circular edge and `AddDiameterDimension2`. Verify the underlying radius-derived value and the reopened dimension value; rounded silhouettes often cannot use the visible-vertex overall operation.
- `Execute` restores or closes its source model after saving/reopening. This can change the active document. Explicitly activate the exact saved SLDDRW before starting the PDF working-copy operation. Do not trust the previous ActiveDoc.
- Selecting the circle with the greatest coordinate along the axis does not establish visibility. Blind-hole bottom rims and openings on rear faces can be completely obscured. `Visibility` measures source circle matches in each planned orientation without saving a drawing. Repair plans can choose another measured rim in the same axis/center group or add a rear/left/bottom view. Update table coordinates and diameters to the actual selected source rim.
- A visible-vertex span can disagree with exact body bounds even when the source contains extremal vertices: those vertices may be obscured in the selected view. Preserve the numerical check. An explicitly identified exact envelope note is a nominal fallback, not an associated dimension and not evidence of complete manufacturing annotation.
- Document ownership must be established before closing or discarding a document. Preserve user-modified sources and unrelated editing sessions. A dead COM connection must not prevent writing the case report.
- One locally observed SolidWorks process exit occurred during PDF copy preparation after a native drawing had been saved. RPC failure identifies loss of the process, not its root cause. Do not attribute it to unclosed windows or memory without diagnostic evidence.
- Keep a fixed part/configuration denominator, separate previously completed samples, retain first failures, and distinguish pipeline delivery from manufacturing quality.
- A saved drawing loaded for verification can keep its native file and referenced model open with write access. The verification-only hash reader uses read access with read/write sharing, while checking unsaved flags and comparing both hashes before/after. It never writes either file. The ordinary source construction guard remains unchanged.
- When writing an envelope note, derive the axis from the exact `bounds_mm` column and the dimension's view/direction. A horizontal span in the right view is model Z, not model X. Recheck axis names as well as numerical values during visual QA.
