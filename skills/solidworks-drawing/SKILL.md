# SolidWorks drawing planner

Use source-assisted mode: read the user's authorized source model, choose a drawing plan, then execute it through the bundled program. The program owns geometry measurements and COM execution; the model owns view choice, section choice, annotation strategy and engineering review. Do not rewrite the executor per part.

Read [the plan contract](references/plan-contract.md) before writing a plan and [tested lessons](references/tested-lessons.md) before executing. Runtime: Windows PowerShell 5.1, an already running SolidWorks, its installed .NET interop DLL, and Python 3 for offline plan validation. Use `scripts/run.ps1`.

For the integrated manufacturing-draft workflow, read [the confirmed drawing profile](references/manufacturing-draft-profile.md). It defines single-part input, a single A4/A3/A2 sheet, adaptive views, DWG layout references and dense-dimension tables. It separates confirmed requirements from implemented operations: the bundled runner still requires saved SLDDRW verification and does not yet implement the complete DimXpert-to-DWG pipeline.

## Workflow

1. Collect facts with `-Mode Inspect -Output <absolute facts.json>`; omit `-Source` to inspect the active saved SLDPRT, or supply the authorized source path and optional configuration. A drawing is not a part: if it is active, use its known source path explicitly. Facts contain exact solid bounds, features, faces, edges, persistent edge references, actual localized model-view names and source hash. Read the compact feature/edge information needed; do not infer dimensions from pixels. Inspect rejects unsaved/modified models and assembly inputs in this version.
2. Author a JSON plan grounded in facts. Evaluate the model's default front/top/right orientations, then select the informative views and verify feature exposure and readable annotation space; add supported sections/opposite views as needed. Detail views may be part of the engineering intent but require an added reusable operation before execution. Reference edges by fact IDs rather than guessing screen locations. Use associated dimensions and attached callouts where readable; when dimensions are numerous or cluttered, choose a table or a mixed view/table presentation. Tie table rows to uniquely identified features and verified coordinate references, preserve required size/location/depth information, and document data sources; a general table is not an associative Hole Table. Separate known facts, engineering choices and unresolved requirements. Never invent materials, tolerances, thread classes or surface finish. Imported B-rep can lack feature semantics: label that uncertainty.
   When circular-edge visibility is uncertain, run `run.ps1 -Mode Visibility -Plan <plan> -Output <new visibility.json>`. This creates and closes an unsaved preview with the planned standard orientations, measures full 3D circle matches and leaves source files unchanged. Add opposite orientations to a preview plan when the relevant face is on the rear. Choose unique visible matches; an interior rim at the largest axis coordinate may be fully obscured. A different rim must come from the same measured axis/center group; update the native coordinate table to its actual XYZ/radius and disclose the change. Do not move a leader to an unrelated visible circle.
3. Run `scripts/validate_plan.py <plan.json>` before any mutation. Then `run.ps1 -Mode Execute -Plan <plan.json> -Output <absolute report.json>`. The runner revalidates internally, checks the source hash/configuration and refuses existing output paths. Output only to a new run directory. Keep the source unchanged; the drawing is the editable native deliverable.
4. Read the execution report. It distinguishes actual measurement checks, annotation counts, view bounds and overlaps, native drawing save/reopen, source integrity and optional PDF export. Reopen verification is mandatory. Layout flags require review, not automatic claims of engineering acceptance. Open the saved drawing in SolidWorks, zoom to fit and give the user a concise result. For visual QA, inspect rendered artifacts if available or ask for the user's native drawing review; counts alone do not prove legibility. Finish the authorized sample loop before expanding to batch work.
   To audit a saved drawing after an interrupted run, use `run.ps1 -Mode Verify -Plan <original plan> -Output <new report>`. It reopens the existing native file, checks annotation counts, dimension values, source/configuration references and unchanged source/native hashes. It rejects modified drawings and already open modified source models. It leaves the verified drawing open for review.

## Limits and repair

For an existing native drawing with model dimensions, read [native annotation layout](references/native-layout.md) and use `scripts/layout.ps1`. This reusable operation selects/deduplicates retained dimensions, adds supported edge-to-edge dimensions and attached notes, resolves optional external rows, checks supplied witness spans, audits save/reopen persistence, exports the two native PDF channels. It does not automatically infer all feature dimensions. Review rendered text and linework plus a feature-coverage checklist; numerical counts alone do not prove a complete drawing. The reference also defines isolation and comparison rules when the user requests a separate blind reconstruction test.

This executor supports saved parts (including multiple solid bodies), existing model orientations, straight full sections, associated horizontal/vertical overall dimensions and circular-edge diameters, attached circular-edge labels, general tables and notes. It does not implement assembly BOM/balloons, automatic GD&T, datum schemes, associative hole callouts, arbitrary feature dimensions, complex offset sections or freeform manufacturing intent. When a requested operation is outside this set, disclose it and add a reusable operation only if necessary within the task; do not silently approximate it with a page graphic.

If execution partially fails, read the report and saved files before retrying. Preserve the failure. Repair the plan in a new output directory; at most three plan repairs for a sample before reporting the precise remaining issue. Do not rerun a whole batch after one sample failure. PDF export is optional and attempted once per run. A file existing after SaveAs failure does not prove successful export. Supplemented PDF annotations must be explicitly identified and cannot substitute for missing native annotations.

For an explicitly requested font/PDF repair of an existing drawing, or when optional SaveAs PDF fails, read [font/PDF repair](references/pdf-font-repair.md). The locally observed Arial Unicode MS SaveAs failure remains unresolved. `scripts/export_pdf.ps1` provides a tested alternative for a saved single-sheet drawing: compose native SaveAs geometry with native PrintOut4 annotations. It produces a composed vector PDF and an editable working drawing copy; report the two-channel composition explicitly. Render and inspect before delivering. This route requires Microsoft Print to PDF, matching paper support and Python with pypdf.

Native CAD operations do not require window screenshots. The model may use previews for judgment and visual QA. This skill does not establish unattended/headless SolidWorks support or claim engineering release approval.

## Authorized batch work

When the user authorizes the whole batch, run `scripts/batch.ps1 -PlanDirectory <absolute directory> -OutputDirectory <new batch directory> -Python <python executable> -InteropPath <installed DLL>`. All native output paths in the plans must be within the output directory; source models must be outside it. With scriptblock invocation set `SW_DRAWING_SKILL_ROOT` to this skill directory. The runner compiles once, processes plans sequentially, writes a durable report per part, composes the two native PDF channels and explicitly activates the saved drawing before export. It skips existing case reports; repairs need new plans/output directories. Preexisting unsaved drawings and modified sources must be preserved.

Do not wait for approval between already authorized parts. Distinguish unsupported drawing intent from missing engineering specifications. Permit at most three deliberate repairs per failed part, then record the error and continue. Render and inspect successful PDFs, including dense tables, turned parts, springs and multibody/imported models. Final delivery needs the completed/failed list, source integrity checks and an honest distinction between nominal geometry drawings and fully specified manufacturing drawings. Document reusable skill changes separately from private part plans. Record native/PDF verification results, repairs and unresolved issues. Never rewrite initial failures as successes after recovery. A nominal measurement note replacing an unsupported associated dimension is a scope reduction and must be listed; PDF creation alone does not prove drawing completeness.
