# 实测架构与数据边界

更新：2026-09-14。原仓库的“只单件、只 MCP”是准备阶段设计，已被用户后续的装配与官方 COM 探索扩展。

| 层 | 负责什么 | 不负责什么 |
|---|---|---|
| 用户与输入资料 | 目标、图纸、授权、缺失尺寸解释、采购件保留策略 | 不能默认提供唯一曲面解 |
| GPT-6 Astra | 图纸/文字理解，特征与装配规划，编写调用代码，解释测量差异 | 不直接实现 CAD 布尔内核或数值配合求解 |
| Codex | 工具执行、文件管理、状态观察、恢复、验证及报告 | 不自动把一段成功会话变成通用产品 |
| COM 参考执行器 | 明确操作 SolidWorks 官方 API，提取/构建/装配/量测 | 不是新 MCP，也不是不依赖安装环境的跨平台 CAD |
| 外部 MCP（可选路径） | 将一组 CAD 操作包装成模型可调用工具 | 不保证拥有全部官方 API 的能力覆盖 |
| SolidWorks | 原生草图/特征、实体几何、配合求解、保存和量测 | API 返回成功不等于符合设计意图 |
| 独立验证 | 合法实体、关键尺寸、草图状态、布尔差分、位姿、干涉、重开检查 | 有限测试不能推出陌生图纸的总体成功率 |

## 输入模式

- blind：仅有二维图纸及用户说明；原模型在建模期间不可访问，输出冻结后再独立评估。
- source-assisted：经授权先从原 CAD 整理图纸、尺寸或装配关系，再依据这些输入重建；必须披露已接触原件。
- vendor-reuse：明确允许保留采购零件/子装配；新建成果和继承内容分别统计，可与 source-assisted 同时使用。

本轮机械手属于后两种组合。初始朝向来自输入中的原变换；非基准件平移打散后，通过真正的配合求解归位。因此不是纯视觉猜测装配，也不是把全部零件固定在目标坐标。

## 执行边界

COM 使用 Windows PowerShell 5.1 + .NET interop，长度 SI 米、角度弧度；图纸 JSON 可用 mm，但转换必须明确。接口封装可能以 mm/deg 暴露，不应混用。仅一个驱动控制共享 SolidWorks 会话。

零件几何执行器读取外置尺寸 JSON。装配执行器读取实例层级、引用路径、局部几何描述与目标朝向提示；不复制自制件原实体。采购模型单独复制并重定向引用，原件不覆盖。

当前七个参考类仍是实验代码。完成跨案例配置、状态恢复、输入防护和更完整的离线回归前，不应升级宣传为通用服务。已有单件 Schema 与完整装配输入并非同一协议。

## 验证链

输入歧义检查 → 单特征检查 → 合法实体/关键尺寸 → 草图与设计语义 → 保存重开 → 原件辅助几何比较 → 配合有效性 → 位姿/朝向 → 干涉基线/自由度。

要同时保留几何失败和工程语义失败。例如：体积精确但材料未设置，配合全绿但模块翻转，实体有效但自由曲面不唯一。细节见 [汇报](PROJECT_REPORT.zh-CN.md)。
